# 00. 핸즈온 제작 지시문 (사내용)

이 문서는 OpenClaw 핸즈온 콘텐츠를 제작할 때 따라야 하는 **필수 기준**을 정의한다.

---

## 1. 필수 운영 원칙

아래 항목은 모두 **필수**다.

1. AWS 인프라는 **Terraform이 아닌 AWS Console**로 생성한다.
2. EC2는 각자 생성한 **개인 키 페어(.pem)** 로 SSH 접속한다.
3. AI 인증은 결제 API 키 대신 **온보딩에서 개인 Google 계정 로그인(OAuth) 경로**만 사용한다.
4. Slack 연동은 공용 워크스페이스가 아닌 **각자 본인 Slack 워크스페이스**에서 앱/봇을 만든다.

## 2. 표준 실습 시나리오

### 2-1. AWS Console에서 EC2 생성

- 리전: `ap-northeast-2` (서울)
- AMI: `Ubuntu Server 22.04 LTS`
- 인스턴스: `t3.small`
- 스토리지: `30GB gp3`
- 보안그룹:
  - `22` (SSH): 본인 공인 IP만 허용
  - `18789` (Gateway): 본인 공인 IP만 허용
  - `443` (선택): 필요한 경우에만 본인 공인 IP 허용

### 2-2. SSH 키 접속

로컬 PC에서:

```bash
chmod 400 ~/.ssh/<내-키페어>.pem
ssh -i ~/.ssh/<내-키페어>.pem ubuntu@<EC2_PUBLIC_IP>
```

### 2-3. OpenClaw 설치 및 온보딩 시작

EC2 서버에서:

```bash
curl -fsSL https://openclaw.ai/install.sh | bash
openclaw onboard
```

채널은 `Slack (Socket Mode)`를 선택한다.

### 2-4. 개인 Slack 워크스페이스에서 앱/봇 생성

- `https://api.slack.com/apps`에서 본인 워크스페이스 선택
- 앱 생성 후 `Bot Token (xoxb-...)`, `App-Level Token (xapp-...)` 발급
- 온보딩 입력 단계에 각 토큰을 입력

### 2-5. 온보딩에서 개인 Google 계정 로그인 인증

- `openclaw onboard` 진행 중 AI 인증 단계에서 OAuth 로그인 흐름을 선택한다.
- 브라우저 인증 단계에서 **개인 Google 계정**으로 로그인 후 승인한다.
- 이 과제에서는 `claude setup-token` 명령 실행 및 수동 토큰 등록을 사용하지 않는다.

### 2-6. 동작 확인

- Slack 채널/DM에서 봇 호출 후 응답 확인
- 대시보드 접속: `http://localhost:18789/?token=<GATEWAY_TOKEN>`
- 점검 명령:

```bash
openclaw doctor
openclaw gateway status
openclaw config get gateway.auth.token
```
