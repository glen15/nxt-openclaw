# 04. 운영 레퍼런스

OpenClaw 운영에 필요한 명령어, 팁, 트러블슈팅, 비용 정보를 통합한 레퍼런스 문서.

## 1. 사용 팁

### 채팅 명령어 (메신저/Chat UI에서 사용)

| 명령어 | 설명 |
|--------|------|
| `/help` | 사용 가능한 명령어 목록 |
| `/reset` | 대화 기록 초기화 |
| `/model` | 현재 사용 중인 AI 모델 확인 |
| `/model claude-opus-4-6` | 모델 변경 |
| `/thinking high` | 깊은 사고 모드 활성화 |
| `/thinking off` | 일반 모드로 복귀 |
| `/verbose` | 상세 응답 모드 |
| `/new` | 새 세션 시작 |

### CLI 명령어 (서버 터미널에서 사용)

| 명령어 | 설명 |
|--------|------|
| `openclaw gateway status` | Gateway 상태 확인 |
| `openclaw gateway restart` | Gateway 재시작 |
| `openclaw gateway stop` | Gateway 중지 |
| `openclaw dashboard` | Control UI 열기 |

### Thinking 모드 활용

복잡한 질문에는 thinking 모드를 사용하면 더 정확한 답변을 얻을 수 있다:

```
/thinking high
이 알고리즘의 시간 복잡도를 분석해줘...
```

> thinking 모드는 토큰 소비가 크다. 간단한 질문에는 `/thinking off`로 돌아가자.

### 멀티 채널 활용 전략

같은 AI 비서가 모든 채널에서 연결되므로, 상황에 맞는 채널을 사용하자:

| 상황 | 추천 채널 |
|------|----------|
| 데스크탑 작업 | Control UI (브라우저) |
| 이동 중 | Telegram 모바일 앱 |
| 팀 협업 | Slack / Discord 서버 |
| 일상 대화 | WhatsApp |

### 스킬 관리

스킬은 OpenClaw의 기능을 확장하는 플러그인이다.

```bash
# 설치된 스킬 확인
openclaw skills list
```

AI에게 직접 스킬 검색과 설치를 요청할 수 있다:

```
나: 날씨 스킬을 찾아줘
AI: ClawHub에서 날씨 관련 스킬을 검색했습니다:
    1. weather-forecast - 날씨 예보 조회
    설치할까요?
```

### 영구 메모리

OpenClaw는 대화 내용을 기억한다. 사용자 정보, 선호도 등이 세션을 넘어 유지된다.

```
# 첫 번째 대화
나: 내 이름은 민수야, 프론트엔드 개발자야.
AI: 안녕하세요 민수님!

# 며칠 후 대화
나: 내 이름 기억해?
AI: 네, 민수님! 프론트엔드 개발자로 기억하고 있습니다.
```

## 2. 외부 접속 설정

Gateway는 기본적으로 `127.0.0.1:18789`에서만 접속 가능하다. 외부 접속이 필요하면 아래 방법 중 선택한다.

### 방법 A: Tailscale (권장)

Tailscale은 VPN 서비스로, 설치만 하면 어디서나 안전하게 접속할 수 있다.

```bash
# EC2에 Tailscale 설치
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
```

출력되는 URL을 브라우저에서 열어 Tailscale 계정으로 로그인한다.

```bash
# OpenClaw에 Tailscale 모드 설정
openclaw gateway --tailscale serve
```

또는 설정 파일에서:

```json
{
  "gateway": {
    "bind": "loopback",
    "tailscale": { "mode": "serve" }
  }
}
```

같은 Tailscale 네트워크에 있는 기기에서 `https://<EC2의-tailscale-hostname>/`으로 접속한다.

| 모드 | 접속 범위 | 인증 |
|------|----------|------|
| `serve` | 같은 Tailscale 네트워크만 | Tailscale ID 자동 인증 |
| `funnel` | 인터넷 어디서나 | 비밀번호 필수 |

> 개인 사용이라면 `serve` 모드로 충분하다. `funnel` 모드는 반드시 강력한 비밀번호를 설정하자.

### 방법 B: Nginx 리버스 프록시 + HTTPS

도메인이 있고 인터넷에서 직접 접속하고 싶을 때 사용한다.

```bash
# Nginx + Certbot 설치
sudo apt install -y nginx certbot python3-certbot-nginx

# SSL 인증서 발급
sudo certbot --nginx -d your-domain.com
```

Nginx 설정 (`/etc/nginx/sites-available/openclaw`):

```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;

    ssl_certificate /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:18789;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/openclaw /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

> 외부 접속을 허용하므로 반드시 Gateway 인증을 설정한다: `export OPENCLAW_GATEWAY_PASSWORD="your-strong-password"`

### 방법 C: SSH 터널 (임시)

별도 설정 없이 내 PC에서 바로 접속하는 방법이다.

```bash
ssh -i ~/.ssh/glen-openclaw.pem -L 18789:localhost:18789 ubuntu@<EC2_ELASTIC_IP> -N
```

브라우저에서 `http://localhost:18789/`으로 접속한다.

> SSH 연결을 유지해야 하므로 임시 용도에 적합하다.

### 어떤 방법을 선택할까?

```
개인 사용, 간단하게 → Tailscale (방법 A)
도메인 있고, 팀/공개 서비스 → Nginx (방법 B)
지금 잠깐 테스트 → SSH 터널 (방법 C)
```

## 3. 운영 및 관리

### 서비스 상태 확인

```bash
# Gateway 상태
openclaw gateway status

# 전체 시스템 진단
openclaw doctor

# systemd 서비스 상태
systemctl --user status openclaw-gateway
```

`openclaw doctor`가 확인하는 항목:
- Gateway 연결
- AI 모델 인증
- 채널 상태
- 보안 설정
- 디스크 공간

### 실시간 로그 모니터링

```bash
# 실시간 로그
openclaw logs --follow

# 특정 채널 로그만
openclaw logs --follow --filter telegram

# systemd 서비스 로그
journalctl --user -u openclaw-gateway.service --no-pager -n 50
```

### 업데이트

**OpenClaw 업데이트**:

```bash
# 방법 1: npm
npm update -g openclaw@latest

# 방법 2: 내장 명령
openclaw update --channel stable

# 업데이트 후 진단
openclaw doctor
```

**Node.js 업데이트**:

```bash
nvm install 22 --reinstall-packages-from=current
nvm alias default 22
```

**시스템 업데이트**:

```bash
sudo apt update && sudo apt upgrade -y
```

| `~/.openclaw/openclaw.json` | 설정 파일 | 매우 높음 |

| `~/.openclaw/agents/` | 에이전트 세션, 메모리 | 높음 |

```bash

```

```bash
# 디스크 사용량 확인
df -h /

```

### Gateway 재시작 및 복구

**정상 재시작**:

```bash
openclaw gateway restart
```

**Gateway가 응답하지 않을 때**:

```bash
ps aux | grep openclaw
openclaw gateway stop
openclaw gateway --port 18789 --verbose
```

**서버 재부팅 후**:

데몬(systemd)으로 설치했다면 자동 시작된다:

```bash
systemctl --user status openclaw-gateway
systemctl --user is-enabled openclaw-gateway

# 자동 시작이 비활성이면
systemctl --user enable openclaw-gateway
systemctl --user start openclaw-gateway
```

## 4. 트러블슈팅

### 진단 도구

문제가 발생하면 먼저 다음 명령어를 실행한다:

```bash
# 1. 전체 시스템 진단 (가장 먼저!)
openclaw doctor

# 2. Gateway 상태 확인
openclaw gateway status

# 3. 채널 상태 확인
openclaw channels status --probe

# 4. 실시간 로그 확인
openclaw logs --follow
```

### 설치 문제

**Node.js 버전이 너무 낮음**

증상: `Error: OpenClaw requires Node.js 22 or higher`

```bash
nvm install 22
nvm alias default 22
node --version  # v22.x.x 확인
```

**npm install 실패**

증상: `EACCES: permission denied`

```bash
mkdir -p ~/.npm-global
npm config set prefix '~/.npm-global'
echo 'export PATH=~/.npm-global/bin:$PATH' >> ~/.bashrc
source ~/.bashrc
npm install -g openclaw@latest
```

**메모리 부족 (Out of Memory)**

증상: `FATAL ERROR: CALL_AND_RETRY_LAST Allocation failed`

```bash
# 스왑 메모리 추가
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# Node.js 메모리 제한 늘리기
export NODE_OPTIONS="--max-old-space-size=2048"
```

### Gateway 문제

**Gateway가 시작되지 않음**

```bash
# 포트 충돌 확인
sudo lsof -i :18789

# 이미 실행 중인 프로세스 종료 후 재시작
openclaw gateway stop
openclaw gateway --port 18789 --verbose
```

**Gateway에 접속할 수 없음**

```bash
openclaw gateway status
ss -tlnp | grep 18789
sudo ufw status
```

**Gateway 토큰 분실**

```bash
# 설정에서 확인
openclaw config get gateway.auth.token

# 또는 새 대시보드 토큰 생성
openclaw dashboard --no-open
```

### 채널 문제

**Telegram 봇이 응답하지 않음**

```bash
openclaw channels status
openclaw logs --follow
curl "https://api.telegram.org/bot<YOUR_TOKEN>/getMe"
```

| 원인 | 해결 |
|------|------|
| 봇 토큰 잘못됨 | BotFather에서 토큰 재발급 |
| 페어링 안 됨 | `openclaw pairing approve telegram <코드>` |
| DNS 문제 | `dig api.telegram.org` 확인 |

**Discord 봇이 응답하지 않음**

| 원인 | 해결 |
|------|------|
| Message Content Intent 비활성 | Developer Portal에서 활성화 |
| 봇 권한 부족 | OAuth URL로 재초대 |
| 페어링 안 됨 | `openclaw pairing approve discord <코드>` |

**WhatsApp 연결 끊김**

```bash
openclaw channels login    # QR 코드 재스캔
openclaw channels status   # 확인
```

**Slack 봇 문제**

| 증상 | 원인 | 해결 |
|------|------|------|
| DM 입력창 비활성화 | App Home Messages Tab 꺼짐 | Slack API > App Home에서 활성화 |
| Pairing code 반환 | 사용자 미승인 | `openclaw pairing approve slack <코드>` |
| 응답 없음 (로그: `missing_scope`) | `im:write` scope 누락 | OAuth scope 추가 후 앱 재설치 |

**그룹 채팅에서 봇이 반응하지 않음**

Telegram:
1. BotFather에서 `/setprivacy` → `Disable`
2. 봇을 그룹에서 제거 후 다시 추가
3. `@봇이름`으로 멘션해서 호출

Discord:
1. 봇에 "View Channels" + "Read Message History" 권한 확인
2. `requireMention: true` 설정 시 멘션으로 호출

### AI 모델 문제

**인증 실패**

증상: `Error: Authentication failed` 또는 `401 Unauthorized`

```bash
openclaw doctor
openclaw auth login anthropic

# 또는 API 키 직접 설정
export ANTHROPIC_API_KEY="your-api-key"
```

**응답이 느림**

| 원인 | 해결 |
|------|------|
| 네트워크 지연 | EC2 리전을 미국으로 변경 |
| 모델이 무거움 | `/model claude-sonnet-4-5`로 변경 |
| thinking 모드 | `/thinking off`로 비활성화 |
| 컨텍스트가 너무 큼 | `/reset`으로 대화 초기화 |

**사용량 한도 초과**

증상: `Rate limit exceeded`

- Anthropic Pro → Max 업그레이드 고려
- thinking 모드 사용 빈도 줄이기
- 불필요한 긴 대화 세션 정리 (`/reset`)

## 6. 레퍼런스

### 설정 파일 구조

```
~/.openclaw/
├── openclaw.json         # 메인 설정 파일
├── workspace/            # 작업 공간
│   ├── skills/           # 설치된 스킬
│   ├── BOOT.md           # Gateway 시작 시 실행할 지시사항
│   └── ...
├── agents/               # 에이전트 데이터
│   └── <agentId>/
│       ├── sessions/     # 대화 세션
│       └── memory/       # 영구 메모리
├── credentials/          # 인증 정보
├── logs/                 # 감사 로그 (command-logger)
├── telegram/             # Telegram 채널 데이터
├── whatsapp/             # WhatsApp 세션 데이터
└── sandboxes/            # 샌드박스 작업 공간
```

### FAQ

**Q: GPU가 필요한가요?**
아니요. OpenClaw는 외부 AI API(Anthropic, OpenAI)를 사용하므로 GPU가 필요하지 않습니다. 가벼운 Node.js 서버만 실행합니다.

**Q: 프리 티어 EC2로 실행 가능한가요?**
t2.micro(1GB RAM)는 메모리가 부족합니다. 최소 t3.small(2GB) 이상을 권장합니다.

**Q: AI 구독 없이 사용할 수 있나요?**
로컬 LLM을 연결할 수도 있지만, 성능이 크게 떨어집니다. Anthropic Claude Pro($20/월) 구독을 권장합니다.

**Q: 데이터는 안전한가요?**
OpenClaw는 셀프 호스팅이므로 데이터가 내 서버에만 저장됩니다. 다만 AI 추론은 외부 API를 통하므로, 대화 내용은 AI 제공자의 서버를 거칩니다.

**Q: 여러 사람이 같이 쓸 수 있나요?**
네. 각 사용자를 페어링으로 등록하고, 별도의 세션으로 관리할 수 있습니다. 멀티 에이전트 라우팅으로 사용자별 다른 설정도 가능합니다.

**Q: 서버를 재시작하면 대화 기록이 사라지나요?**
아니요. 대화 세션과 메모리는 디스크에 저장되므로 재시작 후에도 유지됩니다.

### 용어집

| 용어 | 설명 |
|------|------|
| **Gateway** | OpenClaw의 핵심 서버. 모든 채널과 도구를 관리하는 중앙 제어 플레인 |
| **채널** | Telegram, Discord, WhatsApp, Slack 등 메신저 연결 |

| **스킬** | OpenClaw의 기능을 확장하는 플러그인 |
| **Control UI** | 브라우저에서 접속하는 OpenClaw 관리 화면 (대시보드) |
| **Tailscale** | 간편한 VPN 서비스. 기기 간 안전한 네트워크 구성 |
| **데몬** | 백그라운드에서 자동으로 실행되는 서비스 |
| **온보딩** | 초기 설정 마법사 |
| **Hook** | Gateway 이벤트에 반응하여 자동 실행되는 기능 |
